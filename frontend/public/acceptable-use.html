Acceptable Use Policy (AUP)

Standards of conduct, ingestion quotas, and security boundaries required of all users and automation test runners.

Effective: September 1, 2026

Overview: This Acceptable Use Policy specifies permitted and prohibited uses of the Playwright Dashboard platform, ingestion endpoints, reporter libraries, and real-time streaming sockets.

1. Purpose & Scope

Playwright Dashboard is engineered to empower software teams to build faster, high-reliability test suites. To preserve the reliability, security, and integrity of our shared multi-tenant infrastructure, all customers, automation runners, and API clients must comply with this Acceptable Use Policy.

2. System & Network Security Violations

You may not use or attempt to use the platform to:

  • Launch Denial of Service (DoS or DDoS) attacks against our infrastructure or any third-party services.
  • Probe, scan, or test the vulnerability of our systems without prior authorization under our Responsible Disclosure Policy.
  • Bypass authentication mechanisms, forge JWT credentials, or access projects without authorized permissions.
  • Interfere with or disrupt server operations, Redis message brokers, or PostgreSQL connection pools.
  • Distribute trojans, worms, rootkits, or other malicious code through test reporters or uploaded trace bundles.

3. Abusive & Deceptive Testing Practices

Automated test runners connected to Playwright Dashboard must be configured responsibly:

  • Target Authorization: You must only execute automated Playwright tests against domain names, staging environments, or APIs that you own or have explicit written permission to test.
  • No Cryptocurrency Mining: Running crypto-mining software, proof-of-work scripts, or computational arbitrage via CI runners or embedded test harnesses is strictly prohibited.
  • No Credential Stuffing: Using Playwright test suites to automate credential stuffing, brute-forcing login forms, or scraping copyrighted web properties without consent is forbidden.

4. Prohibited Content in Test Artifacts

When uploading screenshots, video recordings, DOM snapshots, network payloads, and Playwright trace.zip files to our ingest endpoint, you must not submit:

  • Child sexual abuse material (CSAM) or sexually explicit exploitation content (violators will be immediately reported to law enforcement and NCMEC).
  • Unredacted payment card details (PAN / CVV), bank account credentials, or real government identification numbers.
  • Protected Health Information (PHI) subject to HIPAA regulations without an executed Business Associate Agreement (BAA).
  • Stolen trade secrets, confidential third-party credentials, or proprietary source code owned by non-consenting parties.

5. Ingestion Quotas & Fair Rate Limits

To guarantee predictable sub-second latency for all users, the following default ingest boundaries apply:

  • API Ingestion: Standard accounts are allocated up to 120 ingest requests per minute. Burst traffic exceeding 300 requests per minute will receive HTTP 429 Too Many Requests with a Retry-After header.
  • Artifact File Size: Individual trace zip files, video recordings, and failure snapshots must not exceed 50 MB per artifact. Artifacts exceeding this size will be rejected.
  • Concurrent WebSocket Connections: Workspaces may maintain up to 25 simultaneous live dashboard viewer connections concurrently on standard tiers.

Teams requiring custom ingestion throughput for large distributed matrices (10,000+ parallel test workers) should contact our Enterprise team.

6. Webhook & Alerting Fair Use

Automated alerts dispatched to Slack, Discord, Microsoft Teams, or custom HTTP webhooks must not be configured into tight infinite retry loops. If an alert destination repeatedly returns HTTP 5xx errors, our system will implement exponential backoff and temporarily pause delivery.

7. Investigation & Audit

We do not proactively inspect customer test traces under normal operating conditions. However, we reserve the right to investigate reports of abusive activity, unusual traffic spikes, or suspected security breaches.

8. Enforcement & Penalties

Failure to adhere to this policy may result in progressive disciplinary actions:

  1. Warning Notice: Informal or formal notification to the workspace administrator requesting remediation of runaway test runs.
  2. Temporary Rate Throttling: Automated reduction of ingestion limits to protect infrastructure stability.
  3. API Key Invalidation: Immediate revocation of compromised or abusive project ingestion tokens.
  4. Account Suspension / Termination: Complete shutdown of the workspace and permanent forfeiture of services.

9. Reporting Abuse

To report suspected violations of this Acceptable Use Policy, please submit detailed incident telemetry to:

Playwright Dashboard Abuse Desk

Email: abuse@playwright-dashboard.easytesting.app

Escalation response time: Within 24 hours for security incidents.
