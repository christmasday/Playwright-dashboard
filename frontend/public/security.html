Automated Safeguards

Continuous vulnerability scanning, automated dependency auditing via Dependabot, and strict Content Security Policies.

Security Promise: We treat your test code, trace files, and execution metrics with zero-trust rigor. Our infrastructure enforces hardware-level encryption, multi-tenant row isolation, and rigorous token validation.

1. Security Posture & Standards

Playwright Dashboard protects development pipelines by embedding security into every architectural layer. Our controls are designed in alignment with SOC 2 Type II trust services criteria and ISO/IEC 27001 information security management principles.

2. Multi-Tenant Architecture & Workspace Isolation

Our cloud architecture strictly isolates workspace data using both logical and database-enforced controls:

  • Row-Level Security (RLS): PostgreSQL tables enforce cryptographic tenant binding on every query. Workspace members can only query data belonging to authorized organizations.
  • Signed Storage URLs: Artifacts such as trace zips and failure recordings stored in S3/R2 are served exclusively via short-lived, pre-signed HMAC URLs expiring within 15 minutes.
  • Isolated Pub/Sub Channels: WebSocket streaming connections subscribe strictly to tenant-keyed Redis channels; cross-tenant message contamination is mathematically prevented.

3. Cryptographic Standards

  • Data in Transit: 100% of web, API, and WebSocket traffic is protected via TLS 1.3 with modern AEAD cipher suites (ChaCha20-Poly1305, AES-256-GCM). HSTS is enforced with preloading enabled.
  • Data at Rest: Database volumes, backup images, and object storage buckets are encrypted using industry-standard AES-256 with automated KMS key rotation.
  • Credential Storage: User passwords are never stored in plaintext and are hashed using bcrypt with adaptive cost factors.

4. API Token Lifecycle & Ingestion Security

To eliminate the risk of database compromise leaking test runner credentials:

  • Project ingestion tokens are displayed exactly once during generation.
  • Our database stores only the SHA-256 cryptographic hash of the token.
  • Workspace administrators can instantaneously revoke and rotate keys from Workspace Settings if a CI runner is compromised.

5. Backups & Disaster Recovery

We maintain continuous automated backups with point-in-time recovery (PITR) across geo-distributed regions:

  • Recovery Point Objective (RPO): Less than 1 hour.
  • Recovery Time Objective (RTO): Less than 4 hours for complete system recovery.
  • Backup Verification: Automated quarterly restoration drills ensure backup integrity and disaster readiness.

6. Self-Hosted Hardening Recommendations

When self-hosting Playwright Dashboard on Docker or Kubernetes within your internal VPC:

  • Set strong random strings for JWT_SECRET and ENCRYPTION_KEY environment variables.
  • Terminate SSL at a reverse proxy (e.g., Traefik, Nginx, or Cloudflare Tunnel) with modern TLS ciphers.
  • Place PostgreSQL and Redis on private internal Docker networks unexposed to the public internet.

7. Vulnerability Disclosure Policy

We welcome vulnerability reports from security researchers. If you discover a potential vulnerability in Playwright Dashboard:

  • Email our team immediately at security@playwright-dashboard.easytesting.app with detailed reproduction steps.
  • Provide a reasonable embargo period (minimum 30 days) for our engineering team to develop and deploy a patch before public disclosure.
  • Do not view, modify, or exfiltrate customer test data. Test vulnerabilities only against accounts you own.

8. Safe Harbor Commitment

If you conduct vulnerability research in good faith and in compliance with this policy, we will consider your research authorized, will not pursue legal action, and will not request law enforcement intervention.
